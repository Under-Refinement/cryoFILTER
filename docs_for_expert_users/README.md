# cryoFILTER Expert User Notes

This page collects the details intentionally left out of the short public README: OTF visualization controls, particle-filtering behavior, annotation controls, fine-tuning, training, and troubleshooting. For a compact list of command-line flags, see [CLI reference](cli_reference.md).

## Local App

The recommended default interface is:

```bash
cd /path/to/project-or-output-directory
cryoFILTER app
```

The app exposes CryoSPARC-backed prediction, local inference, filter-only particle cleanup from existing masks, live monitoring, annotation, and fine-tuning. The CLI details below are for scripted runs and advanced users.

## Inference Details

Basic inference writes one probability map and one final binary mask per micrograph:

```bash
cryofilter infer \
  --input /path/to/micrographs \
  --output-dir ./cryofilter_output \
  --recursive
```

Default public inference uses the released FULL checkpoint, the balanced small-pixel policy, PSD frequency-band channels, `percentile_extra_wide` normalization, Tukey stitching, and threshold `0.60`.

Useful inference flags:

```bash
--checkpoint /path/to/model.pt
--device cuda
--gpus 0,1
--num-cpus 8
--num-gpus 2
--pixel-size-angstrom 1.06
--threshold 0.60
--inference-profile fast|balanced|quality
--save-mrc / --no-save-mrc
--skip-existing
```

The MRC pixel-size header must be correct unless `--pixel-size-angstrom` is supplied.

## Particle Filtering And OTF Images

Supplying a CryoSPARC `.cs` file or RELION coordinate `.star` file enables particle filtering:

```bash
cryofilter infer \
  --input /path/to/micrographs \
  --output-dir ./cryofilter_output \
  --recursive \
  --particle-file /path/to/particles.cs
```

The input particle file is never modified. Filtered particles are written to `<output-dir>/<particle-stem>_cryofiltered.cs` or `.star`, unless `--filtered-particle-file` is provided.

Particles within `100 A` of a final contamination mask are removed by default:

```bash
--particle-exclusion-distance-angstrom 100
```

For CryoSPARC, a sibling `.csg` file is used automatically when present. You can supply one explicitly:

```bash
--particle-csg /path/to/particles.csg
```

For split CryoSPARC exports, the `.csg` is used as the manifest of all particle-group `.cs` files. cryoFILTER filters every referenced `.cs` by particle UID and writes a matching filtered `.csg` for cryoSPARC import.

Particle micrograph names must match the inferred micrographs. By default, unmatched particles stop the run to avoid partial filtering. To preserve unmatched rows:

```bash
--allow-unmatched-particles
```

With `--particle-file`, OTF images are generated by default in:

```text
<output-dir>/OTF_images/
```

Each OTF image has three panels:

1. Raw micrograph.
2. Micrograph plus predicted mask and particle decisions.
3. Viridis probability map.

Overlay styling:

- Predicted contamination mask: light purple with white outline.
- Kept particles: white circles with blue `#0072BD` outlines.
- Rejected particles: black X marks with orange `#D95319` outlines.

Turn OTF images off:

```bash
--no-render-particle-overlays
```

If masks already exist and you only need to filter later particle picks, use the filter-only command:

```bash
cryofilter filter-particles \
  --input /path/to/micrographs \
  --mask-dir ./cryofilter_output \
  --particle-file /path/to/new_particles.cs \
  --particle-csg /path/to/new_particles.csg \
  --recursive
```

This command requires existing `<micrograph-stem>_mask.npy` files in `--mask-dir` and does not load the segmentation checkpoint.

Useful OTF controls:

```bash
--particle-overlay-dir ./my_OTF_images
--particle-overlay-max-display-dim 1800
--particle-overlay-contact-sheet-cols 1
--particle-overlay-contact-sheet-tile 1100
--particle-overlay-contact-sheet-every 1
--no-particle-overlay-contact-sheet
--no-particle-overlay-raw-panel
--no-particle-overlay-probability-panel
```

## Desktop Annotation GUI Fallback

Create a manifest with one row per micrograph. Use `dataset_id` values to define groups that should stay together during splitting.

```csv
dataset_id,stem,micrograph_path,pixel_size_angstrom
1,FoilHole_0001,/path/to/micrographs/FoilHole_0001.mrc,1.06
1,FoilHole_0002,/path/to/micrographs/FoilHole_0002.mrc,1.06
101,FoilHole_val_0001,/path/to/micrographs/FoilHole_val_0001.mrc,1.06
```

Most users should use the browser-native Annotation tab in `cryoFILTER app`.
The desktop GUI remains available from the repository root in an interactive
display session:

```bash
conda activate cryofilter

cryofilter gui \
  --manifest /path/to/my_images.csv \
  --output-dir ./annotation_exports/my_data_v1
```

Core controls:

- Left click: add polygon points.
- Right click or Enter: close/apply a polygon.
- `x`: polygon erase inside an existing mask.
- `s`: save the current image.
- `q`: save a checkpoint and quit.

The finalized export writes:

```text
annotation_exports/my_data_v1/manifest_edited.csv
```

That edited manifest contains the `gt_mask_path` column used for fine-tuning.

## Fine-Tuning From The Public Model

Use this when the public FULL model misses a contamination style in your data. Keep validation images held out, and inspect validation overlays before adopting the fine-tuned checkpoint.

Set dataset IDs from your edited manifest. Every `dataset_id` must appear in either `TRAIN_IDS` or `VAL_IDS`.

```bash
EDITED_MANIFEST=annotation_exports/my_data_v1/manifest_edited.csv
MIC_DIR=/path/to/micrographs
TRAIN_IDS=1
VAL_IDS=101

python scripts/train_patch_based_fast.py \
  --manifest "$EDITED_MANIFEST" \
  --mic_dir "$MIC_DIR" \
  --pretrained_model pretrained_models/cryoFILTER_FULL.pt \
  --output_dir ./finetune_my_data_v1 \
  --model_type unet_attention \
  --attention_type global \
  --use_psd true \
  --adaptive_downsample \
  --adaptive_downsample_method fourier \
  --target_pixel_size 2.0 \
  --working_patch_size 256 \
  --working_stride 96 \
  --normalization_method percentile_extra_wide \
  --norm_type group \
  --batch_size 16 \
  --num_gpus 1 \
  --num_epochs 120 \
  --lr 2e-5 \
  --warmup_steps 80 \
  --weight_decay 0.01 \
  --decoder_dropout 0.1 \
  --label_smoothing 0.0 \
  --train_dataset_ids "$TRAIN_IDS" \
  --val_dataset_ids "$VAL_IDS" \
  --no_region_gt_fill_holes \
  --full_micrograph_training \
  --full_mic_patches_per_mic 64 \
  --full_mic_overlap 0.625 \
  --full_mic_prefetch_workers 1 \
  --skip_patch_cache_in_full_mic \
  --psd_frequency_band_channels \
  --psd_frequency_bands 0.03:0.05,0.09:0.11,0.14:0.16,0.22:0.24 \
  --use_dice_loss \
  --lambda_dice 2.0 \
  --lambda_focal 1.0 \
  --lambda_edge 0.3 \
  --stitched_val_every_n_epochs 3 \
  --stitched_val_mics_per_dataset 1 \
  --stitched_val_overlap 160 \
  --stitched_val_batch_forward_size 16 \
  --stitched_val_blending_window tukey \
  --stitched_val_blending_edge_px 16 \
  --stitched_val_thresholds 0.05,0.15,0.25,0.35,0.45,0.55,0.70 \
  --stitched_val_metrics_max_samples 3000000 \
  --early_stop_patience 14 \
  --early_stop_min_epochs 30 \
  --early_stop_min_stitched_cycles 10 \
  --num_workers 4
```

These defaults are intended to fit common 24 GB GPUs. On larger-memory cards, advanced users can raise `--batch_size`, `--full_mic_patches_per_mic`, and `--stitched_val_batch_forward_size` after confirming that the log reports nonzero processed micrographs and no CUDA OOM skips.

The run writes:

- `best_model.pt`: best validation PR-AUC/recall-oriented checkpoint.
- `best_score_model.pt`: conservative default checkpoint.
- `best_composite_model.pt`: composite selection checkpoint.
- `stitched_prob_maps/`: validation maps and overlays.

For a fuller protocol, see [../docs/fine_tuning.md](../docs/fine_tuning.md).

## Full Training

For full training from scratch with the full-micrograph recipe, run `scripts/train_patch_based_fast.py` without `--pretrained_model`, provide the full training manifest, and keep dataset-level validation separation. The `cryofilter train` command is the lighter patch-based public training utility for quick checks and small experiments.

Always check:

- Dataset IDs are assigned correctly.
- Validation micrographs are held out.
- `gt_mask_path` points to the final masks you intend to train on.
- Stitched validation overlays match the raw annotations before choosing a release checkpoint.

## Contamination Typing

First run inference, then create a manifest pairing each micrograph with its generated mask:

```csv
dataset_id,stem,micrograph_path,binary_mask_path,pixel_size_angstrom
grid_1,FoilHole_0001,/path/to/FoilHole_0001.mrc,./cryofilter_output/FoilHole_0001_mask.npy,1.06
```

Run typing:

```bash
cryofilter type \
  --manifest /path/to/manifest.csv \
  --output-dir ./contamination_labels
```

Typing uses the frozen publication classifier and the matching `classifier.pt`
from [Zenodo](https://zenodo.org/records/22700873) by default. Place it in
`pretrained_models/` in the checkout, beside a custom CryoSPARC segmentation
checkpoint, or set `CRYOFILTER_CLASSIFIER_CHECKPOINT` to its absolute path.
See [model installation and validation](../docs/publication_classifier.md).
For repeated typing of an expanding manifest, add `--workers 4 --incremental`.
Publication inference uses four CPU threads with this setting and automatically
uses CUDA when available. Per-image prediction records live in
`<output-dir>/.publication_cache/`. Changes to input paths, sizes or timestamps,
manifest values, model artifacts, or inference settings invalidate cached
predictions. Run without `--incremental` to force recomputation.
Live summaries are published at most once per 20 seconds by default
(`--summary-interval`), plus a final update.

The publication model predicts each image independently, so new images do not
change earlier predictions. Completed images and unchanged final outputs are
reused. The older dataset-dependent heuristic and its `.feature_cache/` remain
available with `--classifier heuristic`.

CryoSPARC prediction enables cached background typing by default. Use
`cryofilter cryosparc ... predict ... --num-cpus 8 --typing-workers 2 --live-typing background`
before the inference `--` separator, or choose `--live-typing final-only` to defer it.
`--no-run-typing` disables automatic typing. Auto typing workers use up to four
CPUs, capped by the available CPU allocation; live typing uses at most half the
CPU budget. This setting controls CPU threads for publication inference.
`finalize-run` also accepts `--typing-workers` and reuses cached predictions
from the original run.

Outputs:

- `summary.json`: overall percentages and run metadata.
- `image_contamination_summary.csv`: per-micrograph percentages.
- `dataset_contamination_summary.csv`: per-dataset percentages.
- `component_type_assignments.csv`: one label per contamination component.
- `typed_masks/`: integer masks with `0=background`, `1=Carbon`, `2=Crystalline`, `3=Aggregate`, and `4=Ethane`.

## Troubleshooting

If the annotation GUI fails with Qt/xcb errors on a cluster, try:

```bash
pip install -e ".[gui]"
export CRYOFILTER_ANNOTATION_BACKEND=TkAgg
```

If particle filtering fails with unmatched micrographs, compare the basenames in your `.cs` or `.star` file with the `.mrc` files being inferred. cryoFILTER matches by common basename aliases, but it intentionally stops when the match is ambiguous or missing.

If inference is slow on very small pixel-size data, use:

```bash
--inference-profile fast
```

If you need all available options:

```bash
cryofilter infer --help
cryofilter type --help
cryofilter train --help
cryoFILTER app --help
```
